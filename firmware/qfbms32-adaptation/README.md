# QFBMS firmware adaptation

These two maintained files derive from the supplied VBMS32 Micro 1.0.4 / API 6 baseline in `_reference/firmware/`:

- `hw_vbms32.c` derives from `_reference/firmware/hw_vbms32.c` (baseline SHA-256 `5AB637F4DB713AAF7FF2B883D2B3EA5C277636EDDABF10D7E9CE33F0A1CA9944`).
- `vbms32_micro.lisp` derives from `_reference/firmware/vbms32_micro.lisp` (baseline SHA-256 `94F90424C3932F1E8DAD0665ED2F24932AC851B7FCCC1035B2204CE39E3CD0AB`).

The supplied files remain unchanged. To build/run the QFBMS target, use these adapted files in place of the two same-named baseline files and keep the remaining headers, package files, and configuration from `_reference/firmware/`. Rebase changes deliberately when the upstream baseline changes; do not copy this adaptation back over `_reference/firmware/`.

## Bus-admission changes

The adapted C driver holds GPIO9 high during startup, moves the lower monitor from 7-bit address `0x08` to `0x10`, checks the address write and the remaining config/mode commands, then reads `Cell2Voltage` at `0x10` up to three times. It exposes `bms-set-com` to Lisp only after that read succeeds. Failed setup or three failed reads leave GPIO9 high, return initialization failure, and keep address `0x08` unavailable to BQ transactions. The retry policy is three reads during the same startup; after failure, the application must retry initialization or power-cycle/recover the lower BQ if its address state is uncertain. Upper communication is never admitted based on a log message alone.

All Lisp writes to GPIO9, including `with-com`, `com-force`, charge/CAN-related paths and firmware-version compatibility handling, now call `bms-set-com`. Requests to drive the physical enable low are denied until lower `0x10` verification succeeds. C also serializes gate changes with I2C transfers and rejects `0x08` BQ transactions while the upper path is disconnected, except during the explicit lower-address setup phase.

The corresponding schematic is generated by `_tools/gen_bq_monitor_sheets.py`: TI TMUX154E U204 switches SDA/SCL and its active-low EN connects directly to GPIO9. GPIO9 high opens; GPIO9 low connects. The device specifies powered-off high-impedance I/O. The adapted source implements the software admission condition; it cannot establish electrical rail behavior or bench communication.

## Focused checks

Run `python _tools/check_bq_bus_admission.py` for address-write failure, failed and retried `0x10` verification, successful startup, and repeated Lisp gate-request checks. This is source/model verification, not a firmware build or a bench test. Hardware rails, pull-up sizing, bus loading, timing and powered-state transitions remain subject to the OPEN items in `docs/bq-disconnect-2026-11-03.md`.
